# 디자인 변경 반영

디자인 원문은 **읽기만** 한다. 디자인 프로젝트에 쓰지 않는다.

1. **바뀐 파일 찾기** — `mcp__claude_design__list_files`(project `e13de358-3eeb-4e97-b6a0-9dedc3eaf083`, depth -1)로 etag를 받아 `docs/design/README.md`의 「파일별 etag」 표와 비교한다. 새 파일 · etag 변경 · 크기 변경을 표로 보고한다.
2. **작은 파일은 직접 읽기** — `ios-map.json` · `web-map.json` · 목차 캔버스 · `CLAUDE.md` · 토큰은 `read_file`로 직접 읽는다. 새 화면 ID와 탭, 원칙 변경을 확인한다.
3. **큰 캔버스는 추출** — 화면 캔버스 · DS Motion 등은 하위 에이전트가 `read_file`로 원문을 읽고 화면별 항목(라벨 · 행위자 · 상태 · 액션 · 인터랙션 · 데이터 · 권한 · 이동 · 모션)을 JSON으로 추출한다. 원문을 다시 옮겨 쓰게 하지 않는다(손실 발생).
4. **검증** — 추출한 화면 ID를 맵 파일과 대조(누락 · 중복 0)하고, 표본 1–2개를 원문과 직접 비교한다. 결정(`docs/design/decisions.md`)과 다른 새 화면이 있으면 충돌로 표시한다.
5. **문서 갱신** — `screen-index.md`(화면 · 상태 수), `traceability.md`(새 화면을 REQ에 연결, 연결 안 된 화면 0), `README.md`(etag · 모션 · 누락 · 충돌). 표의 열 수가 어긋나지 않았는지 확인한다.
6. **보고 · 승인** — 바뀐 것, 결정과 충돌하는 것, 갱신한 문서를 보고하고 커밋은 승인 후(한국어 메시지).

주의: 화면 인덱스 · 추적표를 만드는 생성 스크립트는 아직 저장소에 없다(작업 세션의 임시 폴더에 있었음). 다시 만들거나 저장소로 옮기기 전까지는 기존 문서 형식을 그대로 따라 수정한다.
