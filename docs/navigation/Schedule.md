# 스케줄(Schedule) 화면 연결

요약: 이은 화면 16 / 전체 18 (이은 버튼이 하나도 없는 화면: 1j).
구현: `Pum/Pum/Features/Schedule/ScheduleRoute.swift`. 순서의 기준은 흐름 지도 J5 · J6. 완료 콜백(`done`)은 프로토타입이라 `done(true)` 후 이동한다.

| ID | 이름 | 들어오는 길 | 이은 버튼 → 목적지 | 잇지 못한 버튼 |
|---|---|---|---|---|
| 1j | 내 스케줄 · 대타 요청 | 17e의 「이번 주」 · 「대타 요청」 | 없음 | 항목 선택 · 요청 취소 등(흐름 지도에 다음 화면 없음) |
| 1t | 사업장 스케줄 | **사장님 근무 탭 첫 화면(DEC-019)** | 사업장 칩 → 1y 사업장 전환 · 「확인 필요 근무기록 N건」 → 1r · + 근무 추가 → 17b | 필요 인력(9a)으로 가는 버튼(클로저 없음), 승인 · 거절(흐름 지도에 다음 화면 없음) |
| 9a | 필요 인력 입력 | 들어오는 버튼 없음(1t에 클로저 없음) | 닫기 → 뒤로, 추천 받기 → 9b | 가능 시간 요청(흐름 지도에 다음 화면 없음) |
| 9b | 추천 3안 | 9a 추천 받기 | 뒤로 → 뒤로, 상세 보기 → 9c | 안 선택(화면 안 선택) |
| 9c | 절감안 상세 | 9b 상세 보기 | 뒤로 → 뒤로, 요청 보내기 → 17a | 없음 |
| 17a | 다음 주 초안 | 9c 요청 보내기 | 사업장 칩 → 1y, 근무 추가 → 17b, 게시 → 17c | 지난주 복사(흐름 지도에 다음 화면 없음) |
| 17b | 근무 추가 시트 | 17a 근무 추가 | 초안에 추가 → 뒤로(17a) | 시트 안 동작 |
| 17c | 게시 확인 | 17a 게시 | 게시 확인 → 17e (교체) · 취소 → 뒤로 | 없음 |
| 17e | 게시 후 내 스케줄 | 17c 게시 확인 | 이번 주 → 1j, 대타 요청 → 1j | 9d로 가는 버튼(클로저 없음) |
| 9d | 직접 조정 | 들어오는 버튼 없음 | 뒤로 → 뒤로, 적용 → 17d | 없음 |
| 17d | 게시 후 변경 | 9d 적용 | 변경 요청 보내기 → 17f | 없음 |
| 17f | 근무 변경 요청 받음 | 17d 변경 요청 보내기 | 뒤로 · 수락 · 거절 → 뒤로 | 없음 |
| 17g | 대타 요청 받음 | 들어오는 버튼 없음 | 뒤로 · 거절 → 뒤로, 수락 → 10k | 없음 |
| 10k | 휴무 · 변경 요청 처리 | 17g 수락 | 뒤로 → 뒤로 · 승인 · 거절 → 처리 완료 표시(화면 안) | 다음 화면 없음 |
| 2j | 추가 근무 요청 | 들어오는 버튼 없음 | 닫기 → 뒤로, 보내기 → 2k (교체) | 날짜 · 시작 · 종료 · 휴게 · 직접 입력 선택(디자인에 목적지 없음) |
| 2k | 추가 근무 요청 받음 | 2j 보내기 | 뒤로 · 수락 · 거절 → 뒤로 | 10i로 가는 버튼(클로저 없음) |
| 10i | 휴무 신청 | 들어오는 버튼 없음 | 닫기 → 뒤로, 보내기 → 뒤로, 근무 변경으로 → 10j (교체) | 없음 |
| 10j | 근무 변경 요청 | 10i 근무 변경으로 | 닫기 · 보내기 → 뒤로 | 없음 |

화면 수정이 필요한 것: 1t에서 9a로, 17e에서 9d로 가는 버튼과 1j · 2k · 10i로 들어오는 버튼이 View에 없다. 이으려면 View에 클로저가 필요하다.

다음 주 초안이 있으면 근무 탭 첫 화면을 17a로 하는 규칙(DEC-019)은 서버의 초안 여부 값이 생기면 연결한다. 지금 예시 데이터에는 초안 여부가 없어 1t로 연다.
