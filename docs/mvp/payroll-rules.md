# Domain/Payroll — MVP 월급 계산 모듈

결정: DEC-029(기기 안 Swift 계산) · DEC-031(계산 범위). 요구사항: REQ-071(일부). 계획: `docs/mvp/README.md`.

화면 · SwiftData에 의존하지 않는 **순수 함수**다(Foundation만). 같은 입력이면 항상 같은 결과와 계산 근거(Trace)를 낸다.
서버 엔진(`packages/payroll-engine/`, TypeScript)을 붙일 때는 `PumTests/Domain/Payroll/PayrollCalculatorTests.swift`의 사례표로 결과를 맞춘다.

## 공개 API

```swift
let result = PayrollCalculator.calculate(PayrollInput(
    workplace: PayrollWorkplace(isFiveOrMore: true, deduction: .business3_3),
    period: PayrollPeriod(year: 2026, month: 10),
    terms: PayrollWorkTerms(wage: .hourly(10_320), scheduledWeekdays: [.monday, .wednesday], dailyScheduledMinutes: 480),
    records: [PayrollWorkRecord(date: PayrollDate(2026, 10, 5), startMinute: 540, endMinute: 1080, breakMinutes: 60)]
))
result.netPay        // Int(원)
result.traceText     // ["기본급 8시간 × 10,320원 = 82,560원", …]
```

| 타입 | 역할 |
|---|---|
| `PayrollInput` | 사업장 · 기간 · 근로조건 · 근무 기록 |
| `PayrollWorkplace` | 상시 5인 이상 여부 · 공제 방식(`.none` · `.business3_3`) |
| `PayrollPeriod` | 급여 기간(한 달, 1일–말일) |
| `PayrollWorkTerms` | 임금(`PayrollWage.hourly` · `.monthly`) · 주 소정근로 요일 · 하루 소정근로(분) |
| `PayrollWorkRecord` | 날짜 · 시작/끝(분, 자정 넘김은 끝 ≥ 1440) · 휴게 · 휴일 근무 · 결근 |
| `PayrollDate` · `PayrollWeekday` | 서울 달력 날짜(시간대 없는 날짜 산술). `Date` → `PayrollDate(seoul:)` |
| `PayrollResult` | 항목별 금액 · 근무일 · 시간 합계 · `trace: [PayrollTraceLine]` |
| `PayrollRounding` | 반올림 · 절사 규칙(이 파일 한 곳) |

## 계산 규칙

모든 금액은 정수 원, 시간은 분 단위 정수. 부동소수점을 쓰지 않는다.

1. **인정 근무시간** = 끝 − 시작 − 휴게(음수면 0). 결근 기록은 0. 자정을 넘긴 근무는 시작한 날에 속한다.
2. **기본급**
   - 시급제: 시급 × 기간 안 인정 시간(분) ÷ 60.
   - 월급제: 월급 그대로. **결근 공제 없음**(근거에 「월급제 결근 공제 없음(MVP)」). 주휴는 월급에 포함.
3. **주휴수당(시급제만)**
   - 주 = 월요일–일요일. 주 소정근로시간 = 소정근로 요일 수 × 하루 소정근로 시간(약정 기준, 실제 근무 아님).
   - 조건: 주 소정근로 15시간(900분) 이상 + 그 주의 소정근로 요일에 **결근 기록**이 없음.
   - 시간: 주 소정근로 ÷ 40 × 8, 최대 8시간. 금액: 시급 × (해당 주들의 시간 합) — 항목 전체에서 한 번 반올림.
   - **월 경계: 그 주의 마지막 날(일요일)이 속한 달에 지급**한다. 예: 10/26(월)–11/1(일) 주는 11월 급여.
   - 기간 밖 날짜(전 달 말 · 다음 달 초)의 결근도 판단에 쓴다 → 호출하는 쪽이 걸친 주의 앞 달 기록도 넘겨야 정확하다.
   - 기록이 없는 소정근로일은 결근으로 보지 않는다(결근은 `isAbsent` 기록만). 앱은 근로조건대로 근무 기록을 자동으로 채운다(MVP 흐름).
4. **가산(상시 5인 이상만, 각 50%)** — 시급제는 시급, 월급제는 통상시급 = 월급 ÷ 209(원 미만 반올림한 정수)로 **가산분만** 계산.
   - 연장: 하루 8시간 초과분 + 주 40시간 초과분(하루 8시간 이내 시간만 주 누적, 중복 없음). 주는 월–일이며 기간 밖 날짜의 근무도 누적에 쓰고, 지급은 기간 안 날짜의 연장만.
   - 휴일 근무 기록은 연장 계산(하루 · 주)에서 뺀다. 휴일 가산: 그날 8시간 이내 50%, 초과분 100%.
   - 야간: 22:00–06:00과 겹친 분. 휴게는 야간 밖에서 쓴 것으로 보고, 그날 인정 시간을 넘지 않게 자른다.
   - 연장 · 야간 · 휴일은 겹치면 각각 더한다(예: 휴일 야간 = 휴일 50% + 야간 50%).
   - 5인 미만: 가산 0원. 시간(연장 · 야간 · 휴일 분)은 결과에 그대로 센다. 근거에 「상시 5인 미만 — 연장 · 야간 · 휴일 가산 없음」.
5. **공제**
   - 없음, 또는 사업소득 3.3%: 소득세 = 지급 합계 × 3% → **10원 미만 절사**, 지방소득세 = 소득세 × 10%(= 지급액의 0.3%) → **10원 미만 절사**.
   - 실지급액 = 지급 합계 − 공제 합계.
6. **반올림**: 항목별(기본급 · 주휴 · 연장 · 야간 · 휴일) 금액은 원 미만 반올림(0.5원은 올림), 항목마다 한 번. 세액은 10원 미만 절사. 규칙은 `PayrollRounding`에만 있다.

## 노무 검토 필요(출시 전 노무사 확인 · 개발 명세서 부록 B)

- [ ] **주휴 월 경계**: 걸친 주를 「일요일이 속한 달」에 지급하는 방식이 괜찮은지(입사 · 퇴사 주, 퇴사 주 주휴 포함).
- [ ] **주휴 개근 판단**: 결근 기록만 결근으로 본다. 무급 휴무 · 지각 · 조퇴 · 휴가가 개근에 영향을 주는지(명세서 1.7 미정).
- [ ] **주휴 시간 기준**: 약정 소정근로로 판단(실제 근무시간 아님). 4주 평균 방식 · 주마다 근무가 다른 경우 미반영.
- [ ] **월급제 결근 공제 없음**: 결근해도 월급 전액. 일할 계산 · 중도 입사/퇴사 일할 미반영.
- [ ] **월급제 연장 · 휴일**: 통상시급(월급 ÷ 209)으로 50% 가산분만 계산. 연장 시간의 기본 100%분은 월급에 포함됐다고 본 것(포괄 여부에 따라 다름). 209시간 고정(주 40시간 아닌 월급제는 다름).
- [ ] **휴일 정의**: 휴일 근무 여부는 입력(`isHolidayWork`)을 그대로 쓴다. 공휴일 · 근로자의 날 · 약정 휴일 자동 판단 없음. 휴일 근무 시간을 주 40시간 누적에서 뺀 것.
- [ ] **단시간 근로자 가산(REQ-072)**: 소정근로 초과분부터 50% 가산하는 규칙 미반영(하루 8 · 주 40 기준만).
- [ ] **야간과 휴게**: 휴게가 어느 시각인지 모르므로 야간 밖에서 쓴 것으로 가정.
- [ ] **상시 5인 판정**: 입력값을 그대로 씀(규모 산정 방법 미반영).
- [ ] **3.3% 범위 · 소액부징수**: 소득세 1,000원 미만 소액부징수 미반영. 지방소득세를 소득세 × 10%로 계산(지급액 × 0.3%와 10원 단위에서 다를 수 있음).
- [ ] **최저임금 검증(REQ-071)**: 계약 시급 < 최저임금일 때 보정 · 경고 없음.
- [ ] **반올림**: 항목별 원 미만 반올림(사업장 관행에 따라 절사 · 올림을 쓰는 곳 있음).
