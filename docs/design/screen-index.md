> 출처: Claude Design 프로젝트 「근무 관리 급여 시스템」 (`e13de358-3eeb-4e97-b6a0-9dedc3eaf083`), 2026-10-11 조회. 
> 각 캔버스를 MCP `read_file`로 읽어 추출했다. 파일별 etag는 [README](README.md#출처와-버전) 참고.

## 읽는 법

- **UI ID** = `UI-<플랫폼>-<원본 화면 ID>`. 원본 ID(1a, 11a, 16a, 18a…)를 그대로 쓴다. 플랫폼: IOS · WEB · AND(Android) · OPS(운영자).
- **화면 (원문 라벨)** = 디자인 캔버스의 화면 캡션 그대로. 화면 목적은 대부분 이 라벨에 적혀 있다.
- **상태** = 정상 · 로딩 · 빈 · 오류 · 경고/확인필요 · 성공/완료 · 권한/차단 · 시트/다이얼로그 · 알림/푸시 · 기타 중 하나 + 화면이 보여주는 조건.
- **디자인 표시** = 확정 · 지난 안 · 검토 중 · 너무 뺀 안 · 노무 검토 대기 · 미표시. 화면 라벨, 프로젝트 CLAUDE.md, 또는 [사용자 결정](decisions.md)(DEC-nnn)에 적힌 경우만 표시하고 근거를 괄호로 밝혔다. **미표시 = 디자인에 상태 표기가 없음**(확정이라는 뜻이 아님).
- **버전(명시)** = 화면·섹션에 MVP/V1/V2가 적힌 경우만. 출시 로드맵에는 화면 ID가 없어 화면별 버전은 대부분 비어 있다.
- **이동 · 대응** = 화면/메모에서 링크된 화면(`#id`, 다른 캔버스) · `↔`는 다른 플랫폼 대응 화면. `(추정)`은 링크가 아니라 내용으로 추정한 흐름.
- 긴 셀은 `…`로 줄였다. 원문은 디자인 캔버스가 기준이다.

## iOS — `근무급여 iOS 화면.dc.html`


### t1 · 소규모 사업장 근무·급여 앱 — 핵심 화면 (직원 · 사장님) — 포인트 블루

설계 메모 (원문 요약):

- **가정** — 서비스 가칭 「품」(품삯) — 로고·브랜드는 미정 / iOS 기본 문법 + Pretendard · 바탕 연회색(#F3F4F7), 포인트 블루 / 계정은 하나, 상단 사업장 전환 칩으로 사업장·역할이 바뀜 — 직원은 여러 가게에서 일할 수 있음 (1y, 1n) / 예시: 이종민 · 종민김밥 본점 · 시급 12,000원 · 월/수/금 17–22시 / 시급은 직원마다, 사업장마다 다름 — 근로조건은 직원×사업장 단위, 근로계약서(1z)로 확정
- **디자인 원칙** — 예정 vs 실제는 항상 나란히 / 색은 의미로만: 블루=행동·포인트, 초록=확정·금액, 주황=확인 필요, 빨강=결근·거절 / 금액·시간은 고정폭 숫자, 화면당 큰 숫자는 하나만 / 사장님은 "확인 필요한 것만" 처리하는 흐름 / 자동 퇴근 없음 — 예정 시각은 알림·이상 감지에만, 급여는 실제 기록으로만 (1aj~1al, 근무급여 iOS 화면.dc.html#1am)

### t13 · 점장 · 직원 웹 · 랜딩 · 태블릿 · 공용기기(V1 이후) · 로그인

설계 메모 (원문 요약):

- **점장 · 직원** — 점장은 같은 화면에서 메뉴만 줄어듦 — 급여 · 인건비 · 개인정보는 메뉴와 패널에서 빠짐. 직원 웹은 명세서 · 계약서 열람과 내려받기만.
- **랜딩** — "추가 기기 없이 QR 한 장" 중심. 앱 · 웹 화면 자리는 실제 캡처로 교체. 요금 섹션은 요금이 정해지면 추가.
- **태블릿 · 공용기기** — 1024에서는 메뉴를 접고 상세 패널을 위에 겹침, 터치 버튼 44. 동적 QR은 V1 이후 선택 기능 — 기기가 이미 있는 매장용, 필수 아님.
- **로그인** — 앱으로 QR 스캔(기본) 또는 휴대폰 번호 인증. 급여 확정 · 지급 같은 강한 인증은 기능 진입 때 다시.
